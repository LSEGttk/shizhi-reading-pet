# 拾知 · 宠物陪读扩展

Chromium 浏览器陪读扩展。划出不懂的地方，结合原文解释，再将同一个疑惑的追问合并成理解笔记。

[下载最新发行版](https://github.com/LSEGttk/shizhi-reading-pet/releases/latest) · [v0.3.4 安装包](https://github.com/LSEGttk/shizhi-reading-pet/releases/tag/v0.3.4)

- 页面宠物气泡简短解释；长段先说明它在回答什么问题。
- 侧栏展开上下文，独立知识模块按定义、原理、例子、延伸讲解。
- 支持公式、表格、流程图和受约束的交互演示。
- 理解笔记本地保存，可编辑、撤销和导出；使用自己的模型接口。
- 跨网页自动陪读可在设置中主动开启。

## 加载和使用

1. 构建：在此目录运行 `npm ci`、`npm run build`。
2. Chrome 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启开发者模式，选择“加载已解压的扩展程序”，选择本目录的 `dist/`。
3. 在扩展详情中打开“扩展程序选项”，填写聊天补全 API 基础地址、模型 ID、自己的 API Key。保存时授权该 API 域名。本地无鉴权模型可留空密钥。
4. 打开文章，点击浏览器工具栏的“拾知”图标。宠物和简短解惑气泡出现在页面角落。
   可选：在设置中开启“跨网页自动陪读”，授权一次后，新网页自动出现，已打开的网页在切换过去时启用。
5. 选中正文，点击“请它解释”，可在气泡内追问。点“知识讲解”进入独立模块，带入选区或填写知识点，点击开始后按四块展开；点“笔记”查看积累。侧栏保留范围和深度控制。
6. 回答中的原文按钮可回到对应段落；理解笔记支持合并、编辑、撤销上次修改和 Markdown 导出。

打包：`npm run package` 生成当前版本的 ZIP（目前为 `artifacts/reading-pet-0.3.4.zip`）。解压后加载其中包含 `manifest.json` 的目录。没有提交浏览器商店或更改现有网站。

### CRX 安装包

`npm run package:crx` 生成当前版本签名包（目前为 `artifacts/reading-pet-0.3.4.crx`），并输出 SHA-256 与扩展 ID。命令默认使用 `/usr/bin/google-chrome`，可通过 `READING_PET_CHROME` 指定 Chrome 路径。

Linux Chrome 可在 `chrome://extensions` 开启开发者模式后尝试把 CRX 文件拖入页面，并确认安装。若当前浏览器版本或策略拦截，使用上面的“加载已解压的扩展程序”方式。Windows/macOS 的 Chrome 对商店外 CRX 有额外限制，不能保证拖入即装；公开分发应走商店或适用的受管安装渠道。[Chrome 官方说明](https://developer.chrome.com/docs/extensions/how-to/distribute/host-on-linux)

签名密钥保存在 `.private/reading-pet.pem`，已排除版本控制及安装包，文件权限为 600。后续 CRX 更新复用此密钥并提高扩展版本；需要妥善备份密钥。CRX 安装和此前按目录加载的开发版可能是不同的扩展 ID，两者本地笔记不会自动迁移。

## 0.1.1 本地诊断

此版本在设置页增加“本地诊断日志”，默认开启，可随时关闭。最近最多保留 200 条事件，记录读取/模型/上下文/笔记等运行阶段、耗时、计数、HTTP 状态码和错误类别。仅安装本版本后的事件可追溯，无法恢复 0.1.0 没有记录的历史。

日志采用字段白名单，不存储 API Key、模型地址、网页地址、原文、提问、回答或笔记正文；不自动上传。在设置页点“导出诊断日志”得到 JSON 文件，可以查看后手动提供给开发者。关闭日志不删除之前的诊断记录。

0.1.1 CRX 使用和 0.1.0 相同的签名密钥/扩展 ID，可直接更新；无需先卸载。正常的同 ID 更新保留设置、会话和笔记。更新后刷新已开启的文章页，再点一次拾知图标。

## 0.1.2 气泡点破、侧栏讲透

气泡默认 1～3 句、约 40～100 字，直击当前疑惑；支持直接追问、引用跳转、停止和进入侧栏。侧栏默认讲原理和一个新例子，必要时增加设计取舍或有用的应用联系，不强制套固定标题。两者共用话题与笔记。

新增 `teaching` 和 `refine` skill。较长气泡、模板化简答或与已读原文出现较长文字重合时，额外请求同一配置模型做一次质检；不展示草稿，不输出思考过程，不用截字符串删掉条件。合格简答不增加一轮。设置页可关闭“解释自检”。这是启发式检测，不能保证识别所有同义复述或保证教学效果；可继续根据真实反馈调规则。

自检失败保留完整原回答，不覆盖成残句。自动笔记仍是独立请求，可关闭。气泡回答独立于侧栏工作，不要求同时打开侧栏。

## 0.2.0 多种讲解形式

侧栏支持标题、列表、表格、代码高亮与复制、KaTeX 行内/独立公式（含 MathML）、Mermaid/分组关系图/静态 SVG，以及可点行的矩阵实验、可逐步合并的 BPE 实验、带滑块的通用参数计算器。图示可放大查看，320px 窄侧栏保留横向滚动的表格和公式。滑块和示例运算在本地计算，操作状态保存到话题，并在同范围的后续问题中按预算提供给模型；操作并不代表已经掌握。

`skills/presentation/SKILL.md` 定义展示选择和组件数据格式，`src/rich/schema.ts` 校验类型，`src/ui/render.ts` 渲染文字和调度组件，`src/rich/frame.ts` 提供独立沙箱演示。模型输出 Markdown 和受约束的组件 JSON；不直接执行模型给的 HTML/JavaScript。讲解优先简短文字，只在图示或交互能帮助理解时使用；不会每次把所有组件都摆出来。气泡仍以少量文字点破关键。

原文图片在本地提取 HTTPS 地址、说明和图注，供回答按真实 ID 引用。当前聊天只接收图片说明，不会发送像素或假装看到了图片细节。外部 Markdown 图片须点击才加载；插件不自动搜索图片，不编造图片来源。

新插画：在设置的“讲解图片与插画”填写独立图片接口、密钥、图片模型 ID，并启用。支持 `POST /images/generations`，`data[0].b64_json` 或已授权 HTTPS 图片链接；并非所有聊天服务或原生图片协议都兼容。API Key 不自动复用聊天密钥。回答中的生成卡片可先编辑描述，点击后才调用；支持停止，最长180秒。返回图片验证为 PNG/JPEG/WebP 后保存本地，重新打开不会再次生成。若服务使用单独 CDN，在设置授权下载域名；推荐直接返回 base64。服务端已受理时停止或下载失败仍可能产生服务商用量。

数据库从 v1 升至 v2，保留旧笔记和会话，新增媒体仓库。导出的 Markdown 保留图示/组件围栏；普通 Markdown 查看器不一定能运行交互组件，生成的图片请另点下载。图像生成、演示与文字渲染可分别替换，模型接入仍位于 `providers/`。

## 0.2.1 结合本段讲原理，区分气泡和侧栏深度

气泡固定走简短解惑；侧栏深度仅作用于侧栏发出的新请求。侧栏增加模式提示和每条回答的来源/深度标记，历史无标记的记录不猜测其原模式。点“讲透这一处”明确请求原理＋例子，不把此前简答要求带入新的讲解模式。本次保留原有会话同步行为：气泡保存共享话题，已打开的侧栏不实时刷新；没有新增自动同步。

“原理＋例子”要求先结合选区所在段落，把前提/输入如何经过操作或推理得到结果讲清，再走一个对应的小例子。只释义、列符号、给结论/类比，或转去讲远处章节的取舍都不算完成。`focusPassageIds` 标出本次重点；`learningPlan` 只携带当前提问的方向线索和同范围内用户的近期自述/纠正，不是能力画像。当前明确问题优先，历史 AI 讲过不等于用户掌握。没有另外调用分类模型，没有写入长期能力评分。

回答检查新增“缺少机制”和“缺少例子”检测；开启解释自检时最多额外修正一次，携带本段原文、当前问题和用户纠正。它是有限的启发式检测，不能证明讲解正确或用户已经学会；修正失败仍保留完整回答。明确要求简答/不举例或主动请求检验题时尊重该次要求。没有依靠增加字数制造深度。

侧栏回答下方可选“拆开符号讲”“符号已懂，讲原理”或“用小题检验”。点击才发起新请求；第三项仅邀请一道改变单个条件的小题，不默认在每次讲解后测验，也不凭一道题宣布全面掌握。纠正作为话题内用户原话保存，在兼容阅读范围下重新装入下一轮上下文。

气泡直接从内容开始，去掉开头“关键在/关键是”。公式讲解规则区分可学习参数表和查表输出，不能因查表就称其输出“不是中间量”。版本使用同一签名密钥，更新保留本地记录。

## 0.2.2 先理解上下文，原理按需追问

保留已有界面和解释方式。气泡划词与侧栏默认先简短说明选区在附近段落中的含义、指代和必要概念，不自动展开原理、推导或设计取舍。侧栏首次默认简答，“讲懂这一处”尊重当前选中的解释深度；“拆开符号讲”回到简答。“举个例子”只为当前含义服务，不强制借机讲原理。

用户明确追问为什么时按所问解释；点气泡“讲透这一处”或主动选择侧栏“原理＋例子”时，仍按本段机制加具体例子讲解，并保留相应检查。过去问过原理不会自动改变后续划词的默认目的。没有新增解释模式、用户能力分档或同步流程。

## 0.3.0 独立知识讲解模块

气泡、侧栏顶部导航和“陪我读”页提供“知识讲解”入口。打开时带入当前选区，可编辑知识点并选择“只看附近 / 当前文章 / 文章＋笔记”；打开和恢复已有记录不请求模型，点击“开始讲解”才生成。普通划词仍默认简短解释上下文，没有自动切换成四段教程。

完整讲解固定按“定义 → 原理 → 例子 → 延伸”组织，可点击章节导航。定义补够必要概念，原理结合本段解释运作关系，例子走通具体条件到结果，延伸只补一个相关应用、边界或易混淆区别。支持既有公式、图示和交互组件。用户在本模块追问时可只答某一块，不反复输出整套结构。启用自检时，缺少实质章节、机制或例子最多修正一次；仍是启发式检测，不能证明讲解质量或用户掌握程度。

实现分为 `agent/knowledge.ts`（执行入口与话题标识）、`skills/knowledge/SKILL.md`（讲解规则）、`core/knowledge.ts`（结构检查）和 `ui/knowledge.ts`（独立页面状态）。复用已有模型、来源检索、预算和安全展示组件，不需再配置一份聊天接口。原文、补充背景与假设例子应区分，不编造作者动机；没有自动联网搜索。

知识讲解对话使用独立的 IndexedDB 话题键，与阅读简答分开；同范围的少量近期阅读问答可作为起点，收窄范围不会带入更宽范围历史。当前知识点在浏览器会话中记住，关闭再打开同话题会恢复记录而不重新生成。改知识点会切换相应记录；换网页/选区会取消未完成的生成，开始前检查正文版本。

“保存为理解笔记”直接在本地保存完整讲解和已有追问，带来源，保留上一版供撤销；不会让一条短追问覆盖完整讲解。知识模块的保存由此按钮触发，不受普通阅读自动笔记的额外模型请求影响。生成可停止，不完整回答不保存。默认输出上限仍尊重聊天设置；四段或图示生成被截断时可提高该设置。

## 0.3.1 普通侧栏模式与气泡实时同步

普通侧栏默认“结合上下文”，用少量短段解释含义、必要概念和前后关系，不再复用气泡的40～100字限制。气泡继续简短解惑。“原理＋例子”按两个明确分块生成，缺少机制、具体例子或分块时最多修正一次；普通侧栏原样重复近期气泡短答也会触发检查。独立“知识讲解”模块继续按四段工作。

切换解释方式后，页面显示已选方式；新问题直接使用它。想改变已有短答，可点击“按此方式重讲上一问”，会以当前方式重新生成一条回答并保留旧回答；只切换下拉框不自动发起付费模型请求。重讲沿用问题内容，不沿用旧请求的简短要求。

气泡完成并保存后，已打开的侧栏自动刷新对应话题；同页换一处划词时，会跟随该选区的最新解释。同步保留未发送草稿和选择的解释方式，不额外调用模型。侧栏自身正在生成时先排队，结束或停止后再同步；正在查看知识模块时，待回到普通阅读再刷新，保留独立讲解。既有消息的展示节点尽量复用，避免重新加载演示或打断图片生成。

对话改为带稳定ID的逐条追加与局部更新，IndexedDB事务内合并，避免两端拿旧列表整段覆盖。旧记录读入时兼容生成标识，不需要删除或重建数据库。交互参数和图片只更新对应消息。同步通知仅含话题、修订和写入端标识，不含问题、回答、网页正文或密钥；诊断只记录同步计数。

## 0.3.2 长段理解入口与跨网页陪读

默认划出长段时，先点明它在回答什么问题，再用白话讲清主要关系。描述性段落可以说“这段在说明什么”，不硬编问句；明确追问优先，知识讲解和原理＋例子维持各自结构。`learningPlan` 增加选区形态和解释入口提示，首次回答与自检共享；长度/句数只是提示，不把长选区判成基础差。允许能降低理解门槛的白话转述。

气泡增加“再白话点”和“不是问这个”。前者直接针对当前话题重讲；后者聚焦输入框，填写后发送才请求模型。反馈仍作为同话题、同范围近期用户原话使用，没有跨文章长期能力画像，也不因模型讲过就视为掌握。

设置新增“跨网页自动陪读”。默认关闭，开启时请求可选网站权限。新网页自动挂载，已有标签切换后补挂载；仅顶层普通 HTTP / HTTPS 页面。出现宠物不会请求模型，也不会立即解析正文；只有划选、提问或侧栏读取时才提取。不会因自动激活再次弹开气泡或恢复用户收起的宠物。关闭后停止未来自动挂载，当前页面可收起或刷新。

网页注入由 `reader/activation.ts` 统一管理，工具栏与侧栏复用去重入口。侧栏在网页加载完成后重读，并丢弃快速切页时迟到的旧结果。构建压缩脚本，内置规则并行加载。代码结构审查见 [ARCHITECTURE_REVIEW.md](ARCHITECTURE_REVIEW.md)。使用同一签名密钥，覆盖更新，无需卸载；更新后刷新旧文章页。

## 0.3.3 选区与参考上下文分开

修正长段气泡容易提前概括下文的问题。生成与自检共用一条回答边界规则：默认讲解对象是选区确切文字，包含选区的段落和其余材料只是理解依据；引用有效不代表结论切题。允许引用相邻段落补定义、指代或必要条件，但不主动带出下文的独立观点。明确要求比较、全文总结或延伸时仍按请求展开。

默认划词气泡不再为填满预算而追加整篇其余段落，保留附近及相关检索结果、按需补读能力。显式提问、普通侧栏和知识讲解的资料范围不因此收窄。规则无法保证模型每次都遵守；没有用字符串截断或删掉所有下文的方式掩盖问题。回归使用“模型扩展与旧 state_dict”选区和相邻“参数×20”段落验证两轮规则传递与资料边界。

## 0.3.4 首个公开发行版

发布前使用本机 Entire CLI 审查，修复四处问题：侧栏发送前更新选区并装入对应话题历史；按话题串行化跨标签/后台的自动笔记合并，避免并发覆盖或重复建笔记；无效气泡请求显式结束并恢复可提问状态；JSON 接口响应与流式响应一样拒绝截断或未正常完成的内容。长标题截到协议允许的长度，保持提取与校验一致。

类型检查、49项单元测试和对话/富内容/跨网页三组 Chrome 回归通过。新增真实浏览器测试覆盖新选区、主动清除选区与跨上下文笔记合并。审查摘要见 [发布审查记录](docs/RELEASE_REVIEW.md)。模型质量仍需用实际接口验证。

## 模型

当前实现聊天补全协议：`POST {baseUrl}/chat/completions`，支持 SSE 流式响应及函数工具调用。输入基础地址时保留 `/v1` 等路径，也接受完整补全地址。HTTPS 服务和本机 HTTP 模型可用。

首次安装没有内置密钥、没有默认模型 ID；自行填写服务商提供的 ID。填写密钥不等于购买了调用额度。模型需支持聊天补全协议；工具调用不兼容时，在设置关闭“允许 AI 按需补读原文”，代码仍会预选相关段落。其他厂商原生协议以后通过 `providers/` 适配。

回答后自动整理笔记会额外发起一次模型请求，可在设置关闭。取消、超时、模型出错或整理失败不会覆盖旧笔记；解释成功而整理失败时，可在该条回答下手动整理。

## 上下文和 skill

- 每次请求动态组装选区、附近原文、章节、匹配的 skill、适用的近期对话。
- `passage` 范围只装入附近段落，不暴露全文或笔记工具；由更宽范围生成的历史回答不会重新带入窄范围请求。
- `article` 范围允许搜索与补读当前页；`notes` 范围额外允许检索本地理解笔记。
- 一个执行器最多进行 2 轮工具补读、4 次工具执行，再生成最终回答；工具不能任意执行 JavaScript 或访问任意网址。
- token 数为 UTF-8 字节估算，包含规则、工具定义和补读结果；与服务商分词统计不完全一致。按配置预算限制，服务商上下文窗口仍需自行匹配。
- 不依靠提示词缓存保存状态。笔记和话题记录保存在本地 IndexedDB；设置保存在扩展 local storage。
- 当前通过词汇匹配和结构定位检索，没有向量模型、外部知识库或重新训练。

修改 `skills/*/SKILL.md` 后重新构建、重新加载扩展，下一次请求会加载新规则。普通模型 API 不会直接读本地文件。

## 权限与数据

默认只有 `activeTab`、`scripting`、`storage`、`sidePanel`。用户点击扩展时临时授权当前网页，不默认常驻读取所有网站。未开启自动陪读时，跨域页面导航后应再次点击图标。自动陪读需主动开启并授权 HTTP / HTTPS 网站访问，使用持久动态内容脚本；设置、权限撤销与后台重启时校验注册状态。浏览器受限页面不注入。关闭后不再自动注入，已存在的宠物在刷新后消失；保留网络域名权限，避免影响模型/图片接口，可在浏览器扩展设置中管理。API 域名权限在保存设置时按需申请。

网页正文先在本地处理，主动提问时将本次组装的材料发送至配置的模型服务，若开启自动笔记则再发送相关问答用于合并。API Key 不同步、不给网页脚本、不出现在消息或日志中；密钥以扩展本地配置形式保存，非操作系统密钥链加密存储。网页 content script 的 storage 访问被限制。

侧栏自己的请求由侧栏持有。气泡请求通过扩展内部 Port 在后台执行，密钥不传到网页；只在活动请求期间每 20 秒发送一次保活消息，结束后停止。关闭/离开网页或 Port 断开会取消气泡请求；单次最长 150 秒。浏览器仍可能意外终止后台，此时气泡提示重试，不把未完成回答保存为笔记。收起气泡只隐藏界面，停止请求请点“停止”。没有默认持续调用模型。

## 目前边界

支持普通 HTML 文章。复杂应用页面、跨域 iframe、浏览器内部页、付费隐藏正文、视频、图像或扫描 PDF 不在当前范围。超长页最多提取前 160,000 字符 / 1,000 个段落，界面会提示。没有跨设备同步、向量检索或长期用户能力诊断。

公式优先保留网页已有的 TeX / 文本，部分图片公式和复杂 MathML 可能无法完整提取；回答支持安全的 Markdown 与 KaTeX 公式排版；图片中的公式仍不能自动识别。

宠物复用指定上游版本的图像与部分呼吸/朝向表现，保留许可及素材校验记录。原图权利来源尚需正式发布前核对或更换自有皮肤，详见 `THIRD_PARTY_NOTICES.md`。当前没有复用声音、主动闲聊和桌面窗口功能。

## 验证

```bash
npm run typecheck
npm test
npm run build
npm run test:browser
npm run test:rich
npm run test:activation
```

浏览器测试默认使用 `/usr/bin/google-chrome`，通过 DevTools 的 `Extensions.loadUnpacked` 加载测试包。可用 `READING_PET_CHROMIUM=/绝对路径/chrome npm run test:browser` 指定支持该接口的浏览器。测试使用独立临时资料目录，不修改用户浏览器资料。

端到端测试使用模拟模型，验证工具补读、流式返回解析、引用、笔记合并/编辑/撤销、会话恢复、范围控制、中止和正文变更。通过 DevTools 的浏览器工具栏 action 验证 `activeTab` 注入与 content script 密钥隔离。测试专用复制包仅预授予模拟模型域名权限；侧栏页面在自动化标签页中渲染，原生侧栏窗口表现及 API 权限弹窗仍需手动检查。测试域名通过本地 HTTP 模拟响应，没有访问外部模型。截图及结果生成到 `artifacts/`。真实模型质量和费用仍需配置有效 API 后验证。

多形式讲解测试使用固定讲解样例和模拟图片接口，验证渲染、隔离、计算、图片保存、数据库升级及窄屏；不代表真实模型必然选择正确的组件，也不代表已验证付费图片服务。

自动陪读浏览器测试单独使用预授网站权限的临时扩展，验证真实动态注册、跨域标签切换、HTTP 页面、刷新、关闭开关、侧栏导航和迟到响应；模拟拒绝授权以验证设置提示。缺少权限/撤销授权由单元测试验证。原生授权弹窗和真实服务商讲解质量仍需人工验证。
